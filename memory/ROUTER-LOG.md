# Лог решений роутера

> Механизм для сбора матрицы ошибок роутера (был заявлен в реестре гипотез H11/H13, но не существовал как файл — см. `FABLE5-REVIEW.md` P1-2). Пишется **только** для нетривиальных/сомнительных решений роутера (value-gate на сам лог — не логировать каждый тривиальный запрос, иначе лог сам станет оверхедом).

## Когда писать строку
- Роутер (Фаза 0) засомневался в классификации (принцип 4: под-роутинг молчалив, при сомнении — пометить).
- В конце сложной задачи (Фаза 7), если задним числом видно, что классификация была неточной (слишком тяжёлая или слишком лёгкая).

## Формат строки
`ДАТА · запрос (≤5 слов) · класс (тривиальный/средний/комплексный) · подключённые модули · ретроспективно верно? (да/под-роутинг/над-роутинг)`

## Как читать (для Overseer, еженедельно)
Матрица ошибок: сколько строк — «под-роутинг» (приоритетный сигнал, он молчалив по умолчанию) против «над-роутинг» (виден по цене, менее срочен). Паттерн — предложи правку триггера конкретного модуля/роутера в `HYPOTHESIS-LEDGER.md`, не молчаливо переписывай `CLAUDE.md`.
