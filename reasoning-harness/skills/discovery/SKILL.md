# Режим изобретения / discovery (M20)

Назначение: получать действительно новые решения там, где это возможно — по доказанному рецепту (FunSearch → AlphaEvolve): **генератор + верификатор + эволюционный цикл**.

## Шаг 0 — построй верификатор (главный шаг)
Определи, **можно ли результат автоматически проверить** (тест, метрика, фитнес-функция, симуляция).
- **Верификатор есть** → переходи к циклу ниже. Возможно настоящее изобретение.
- **Верификатора нет** (философия, стратегия, «прорывная ли идея») → НЕ имитируй открытие. Перейди в режим гипотез (внизу).

## Цикл (если верификатор есть)
1. **Генерация:** предложи много разных кандидатов-решений.
2. **Оценка:** прогони каждого через верификатор, получи балл.
3. **Отбор + мутация:** оставь лучших, видоизмени, повтори несколько итераций.
4. Верни лучшего кандидата + результат проверки.

## Режим гипотез (если верификатора нет)
Выведи гипотезу из явных посылок (как теорему из аксиом, покажи цепочку), пометь `[Предположение]`, проверь лучшим доступным прокси (`red-team`, экспертная рубрика, исторические аналогии, рыночный тест) и запиши в реестр гипотез для проверки практикой. Честно маркируй как недоказанное.

## Не делай
- Не называй правдоподобный текст «открытием» без верификатора.
- Не пропускай Шаг 0 — без него цикл бессмыслен.
- **Cost-gate:** не гоняй полный цикл генерация→мутация, если задача решается аналитически за один шаг; цикл — только там, где one-shot-анализа недостаточно.
- Скоринг-матрицы помечай как `[Предположение]` — защита от ложной точности (оценка некалькулируемого по выдуманным шкалам).
