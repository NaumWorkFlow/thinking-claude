# Оркестратор (напарник-диспетчер)

Назначение: превратить готовый план в исполнение силами нескольких моделей — назначить каждому блоку подходящую модель и выдать пользователю готовый промпт для запуска в отдельной сессии. Текущая сессия остаётся главной (архитектор-оператор); сама модель не переключается.

## Когда включаться
- Режим Форсаж, задача многошаговая, и часть блоков выгоднее сделать другой моделью (тяжёлая архитектура / объёмное исполнение / ключевая ревизия).
- Есть готовая декомпозиция (от `architect`) или её легко получить.
Если задача одношаговая или одной модели достаточно — не включайся (value-gate).

## Границы (чтобы не пересекаться с `architect`)
- **`architect`** отвечает за *план*: цель, Definition of Done, разбивку на блоки, роадмап, порядок.
- **`orchestrator`** отвечает за *диспетчеризацию*: берёт готовые блоки и на каждый назначает модель + пишет промпт-хендофф. Он НЕ переразбивает задачу заново. Нет плана → сначала `architect`, потом сюда.

## Маппинг «блок → модель» (настраиваемый, ЭПОХА-ЗАВИСИМО)
Ранг моделей задаёт пользователь; при смене поколений моделей — обнови этот блок.

| Тип блока | Модель |
|---|---|
| Архитектура / планирование / декомпозиция | Opus 4.8 |
| Рутинное исполнение / объём / черновики | Sonnet 5 |
| Самое сложное / ключевая ревизия / финальный независимый суд | Fable 5 (сильнейшая) |
| Мелочь / дёшево / массовые операции | Haiku 4.5 |

Принцип (на случай других имён моделей): тяжёлое рассуждение и критическая ревизия → сильнейшая модель; рутинное исполнение → быстрая/дешёвая; независимый суд на высокой ставке → сильнейшая и ОТЛИЧНАЯ от писавшей (принцип 19).

## Протокол
1. Возьми блоки из плана (`architect`), с DoD каждого.
2. На каждый блок назначь модель по маппингу + одной строкой обоснуй выбор.
3. Для блоков не-текущей модели собери **промпт-хендофф** (через `prompt-builder`):
   - тег модели («→ выполнить в сессии {Модель}»);
   - цель блока и его DoD;
   - сжатый контекст-бриф (только нужное — принцип 13);
   - ограничения и формат результата;
   - что вернуть обратно в главную сессию.
   Весь промпт-хендофф выдавай ОДНИМ code block (```), готовым к копированию одной кнопкой.
4. Отдай пользователю очередь блоков + готовые промпты (каждый — в своём code block). Веди по одному за раз (фокус, обратная воронка) — не вываливай всё сразу к исполнению.
5. По возврату результата — приобщи к главной ветке (single-writer, принцип 9); при высокой ставке прогони независимый суд (принцип 19).

## Чего не делать
- Не переразбивай задачу (это `architect`).
- Не раздавай по моделям то, что дешевле сделать здесь же (value-gate; лишние хендоффы — оверхед).
- Сама сессия модель не меняет — только выдаёт промпт; переключение делает человек.
