# Кастинг ролей (M4)

Назначение: посмотреть на задачу глазами нужных специалистов, чтобы поймать то, что одиночный взгляд упускает.

## Когда включаться
Задачи, где помогает экспертная оптика: лендинг (маркетолог, психолог, UX-дизайнер), полноценный сайт (+ senior-разработчик, спец по ИБ), продукт/стратегия/контент. Если задача чисто фактическая или вычислительная — не включай (роли вредят точности).

## Процедура
1. **Нужны ли роли вообще?** Если нет — скажи и не раздувай (value-gate).
2. **Сколько и какие?** Определи по релевантности (эффект × усилия), не фиксируй число заранее. Подбери роли, реально полезные этой задаче.
3. **Упущенные роли.** Предложи 1–2 роли/аспекта, о которых пользователь мог не подумать, и спроси: «добавить роль X?».
4. **Взгляд от каждой роли.** Каждая роль даёт мнение *со своей* позиции — конкретно, не общими словами. Помечай, где роль расходится с другими.
5. **Сведение.** Собери выводы ролей в связную картину: где согласие, где конфликт, что делать. **Сохрани полезные кросс-доменные аналогии и переносы, если они есть** — не давай ролевой структуре их вытеснить; при необходимости подключи `adjacent-fields`.

## Оговорка (важно)
Роли улучшают генерацию, дизайн и критику, но **снижают фактическую точность**. Поэтому: фактические утверждения внутри ролевого ответа всё равно проверяй через fact-mode; роли — не способ «знать лучше», а способ «увидеть шире».

## Выход
Список ролей с обоснованием выбора + мнение каждой + сведённая картина (согласие/конфликт/рекомендация).

## Не делай
- Не плоди роли ради числа — только релевантные.
- Не выдавай ролевое мнение за факт.
- **Не выбрасывай рабочие кросс-доменные аналогии ради ролевой структуры.** Если из другой сферы есть сильный аналог (как Strava/Duolingo для продукта) — сохрани его.
