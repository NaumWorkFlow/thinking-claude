# Память + реестр гипотез (M12+M13)

Назначение: превратить разрозненные сессии в накапливающуюся систему — помнить контекст, решения и проверять гипотезы практикой. Реализация файловая: `memory/PROJECT-MEMORY.md` и `memory/HYPOTHESIS-LEDGER.md`.

> Честная оговорка: это не «магическая» автопамять. Память работает ровно настолько, насколько ты (ассистент) читаешь её в начале и пишешь в конце по правилам ниже.

## В начале сессии
1. Прочитай `memory/PROJECT-MEMORY.md` — подними релевантный контекст (только то, что относится к текущей задаче; принцип минимально достаточного контекста).
2. Загляни в `memory/HYPOTHESIS-LEDGER.md` — есть ли активные гипотезы, которые эта задача может подтвердить или опровергнуть.

## В конце сессии / на чекпойнтах
Запиши в память **только долговечное** (политика захвата):
- ✅ Хранить: решения и их обоснование, устойчивые предпочтения, состояние проекта, важные `[Предположение]`.
- ❌ Не хранить: праздное любопытство, разовое исследование, чужие темы (например, вопросы супруги), сиюминутные детали.
- При неоднозначности — спроси или не пиши.

## Правила памяти

**Пространства имён (scopes).** Помечай каждую запись: `[проект:<имя>]` / `[личное]` / `[эксперимент]` / `[чужое]`. Не смешивай рабочий контекст с мусором.

**Отмена устаревшего.** Приоритеты меняются. Новая запись может отменить старую: помечай `ОТМЕНЯЕТ: <старое>` и переноси старое в раздел «Архив» с датой. Не считай устаревшее решение действующим.

**Реестр гипотез (связь с принципом 18).** Каждое важное `[Предположение]` — строка в `HYPOTHESIS-LEDGER.md`: утверждение · основание · предсказание (что увидим, если верно) · статус · свидетельства · решение (оставить/править/убрать). По мере накопления данных двигай статус: `непроверено → подтверждается → [Факт]` либо `опровергнуто → убрать`.

**Консолидация.** Периодически чисти память: объединяй дубли, убирай протухшее, держи индекс коротким (в этой среде есть скилл `consolidate-memory` — можно переиспользовать).

**Репо-память vs платформенная память (P2-2).** Две системы памяти не дублируют друг друга:
- **В репо** (`memory/*.md`, версионируется git, переносимо между средами): реестр гипотез, системные решения, состояние проекта.
- **В платформенной памяти Cowork** (не версионируется, живёт в аккаунте): предпочтения пользователя, межпроектный контекст, всё, что не специфично для этого репо.
Если запись годится в оба места — держи её в репо (проверяемо, версионируется); платформенную используй только для того, что вне scope этого проекта.

## Выход
Обновлённые `PROJECT-MEMORY.md` и `HYPOTHESIS-LEDGER.md` + краткая строка пользователю: что именно запомнил/обновил.

## Не делай
- Не захламляй память мусором «на всякий случай».
- Не выдавай устаревшие приоритеты за текущие — сверяйся с разделом «Архив».
