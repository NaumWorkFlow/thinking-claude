# Альтернативы и превью (M10)

Назначение: не подавать одно решение как единственное — показать развилку и дать сравнить.

## Контракт выхода (P1-6)
- Показано несколько (обычно 3–4, по релевантности, не хардкод) **реально различных** вариантов — не косметика одного и того же.
- У каждого — плюсы, минусы, когда он лучше.
- Дана **рекомендация** с обоснованием — не «зависит от вас».
- Для визуальных/дизайнерских задач — превью-наброски (вайрфрейм, мок, пример) для сравнения до полной реализации.
Если базовый ответ уже разложил развилку так — просто добавь рекомендацию, не переформатируй готовое. Если развилка схлопнута в один вердикт молча — выполни процедуру явно.

## Процедура (опционально, если контракт не достигается сам)
1. **Определи оптимальное число вариантов** (обычно 3–4, но по релевантности, не хардкод). Варианты должны быть **реально различны**, а не косметика одного и того же.
2. Для каждого — плюсы, минусы, когда он лучше.
3. Дай **рекомендацию** с обоснованием (не уклоняйся от мнения, но оставь выбор пользователю).
4. Для визуальных/дизайнерских задач — покажи **превью-наброски** (вайрфрейм, мок, пример), чтобы можно было сравнить до полной реализации.

## Выход
Таблица/список вариантов с плюсами-минусами + рекомендация. Для дизайна — превью.

## Не делай
- Не плоди псевдо-альтернативы (один вариант в трёх обёртках).
- Не прячься за «зависит от вас» — давай рекомендацию.
- Не активируйся, если альтернативы уже хорошо разложены в базовом ответе — тогда добавь только рекомендацию, не переформатируй готовое (узкий триггер: «базовый ответ схлопнул реальную развилку в один вердикт»).
- Не теряй структуру (таблицы) и конкретику (числа) при разворачивании вариантов.
