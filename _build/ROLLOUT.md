# Этап 2 — план роллаута модулей и авто-тестирование

Гибрид между «тестировать по одному» и «собрать всё разом»: инфраструктуру ставим безоговорочно, качество-меняющие модули катим порциями через быстрый A/B-тест, где ты — судья на 1 клик.

## Вердикт по идее (честно)

Идея рабочая, но с жёсткой поправкой по принципу **verifier-first**: **полностью убрать тебя из цикла нельзя.** Для твоих задач (бизнес, стратегия, тексты) нет объективного авто-проверяющего — «лучше ли стал этот роадмап?» другой ИИ надёжно не оценит. Хуже: модель склонна **завышать оценку своему же варианту** с модулем (self-preference bias). Поэтому верификатор качества — ты. Но мы автоматизируем всё *вокруг* твоего суждения, и тебе остаётся роль судьи «A или B». Это и есть быстрый результат без растягивания резины.

## Кто что делает

- **Агент (автоматизировано):** генерит тест-промпты под твою реальную работу; гоняет A/B (без модуля / с модулем); раскладывает сравнение рядом; делает структурную проверку («модуль вообще отработал как задумано?»); пишет вердикт в реестр гипотез; предлагает решение keep / tweak / drop.
- **Ты (секунды):** жмёшь «A лучше / B лучше / без разницы» и подтверждаешь решение.

## Тиры модулей

**Tier 1 — ставим безоговорочно** (инфраструктура + уже подтверждённое практикой):
- Ядро + 4 скилла Этапа 1 — ✓ уже стоят, отработали в Cowork.
- **Память + реестр гипотез (M12+M13)** — фундамент: без него негде хранить результаты тестов и накапливать контекст.
- **Overseer (M21)** — сам наблюдатель и тест-харнес.

**Tier 2 — катим через A/B-тест** (меняют качество вывода → нужно твоё суждение): Роли (M4), Смежные сферы (M6), Топ-N/ландшафт (M7), Альтернативы/превью (M10), Пре-мортем (M15), Стилман (M16), Амплификатор (M19), Приоритизация (M17), Дивергентный (M11), Изобретение (M20). По 1–2 за заход.

**Tier 3 — конфиг, set-and-forget:** Дирижёр модели (M8) — просто разумные дефолты, тестировать нечего.

## Как это работает технически — два режима

**1. Пассивный (Overseer во время обычной работы).**
Ты просто работаешь над реальными задачами в сессии. Overseer — это стоячая инструкция + периодический проход (на чекпойнтах / по расписанию, не непрерывно). Обратную связь он собирает **из самого хода работы**: что ты принял, что отверг, что переспросил, где попросил переделать. На паузах подмечает: «модуль X сработал не к месту», «ты третий раз просишь Y — возможно, нужен модуль Z». Твоего участия — минимум.

**2. Активный (роллаут-тест нового модуля).**
Ты запускаешь команду `/test-module <имя>`. Дальше агент:
1. генерит 3–5 тест-кейсов под твою реальную работу;
2. прогоняет каждый дважды — **без** модуля и **с** модулем (A/B через субагентов с разным контекстом);
3. показывает оба вывода рядом + строку «что именно изменил модуль»;
4. ты тыкаешь A / B / без разницы;
5. агент суммирует, пишет вердикт в реестр гипотез, предлагает keep / tweak / drop;
6. ты подтверждаешь — модуль остаётся или уходит в архив с пометкой почему.

Авто-генерация тест-промптов — полностью на агенте (ты не пишешь их сам). Структурные проверки («fact-mode реально добавил источники?», «red-team выдал приоритизированный список?») агент делает сам; качество судишь ты.

## Где делать: Claude Code (мастерская) + Cowork (работа)

- **Claude Code — сборка и тесты.** Он умеет читать/писать файлы скиллов, включать/выключать их, гонять субагентов с разными конфигами и моделями, скриптовать A/B. Тут живут харнес `/test-module` и весь роллаут.
- **Cowork — твоя ежедневная работа,** где методология помогает, а Overseer пассивно наблюдает.
- Общие `CLAUDE.md` и `skills/` — одна система, две точки входа. Строишь/тестируешь в Claude Code, пользуешься в Cowork.

## Порядок действий

1. Собрать Tier 1 (Память+Реестр, Overseer) + лёгкий харнес `/test-module` + файл-шаблон реестра гипотез. Развернуть в Claude Code одним paste-промптом.
2. Гнать Tier 2 по 1–2 модуля через харнес — быстро, ты только судишь A/B.
3. Что прошло — остаётся; что нет — в архив с причиной. Реестр гипотез копит историю решений.

## Оговорка против переусложнения

Харнес держим **простым**: шаблон промпта + файл реестра, а не тяжёлый фреймворк. Если ловишь себя на том, что настройка тестов занимает больше времени, чем экономит — это сигнал упростить. Overseer обязан резать лишнее так же, как добавлять.
